## 一、这次实战的样本量

同一篇笔记，正文改了 9 个版本（v1 → v9），封面改了 6 个方向（v3a/b/c、v4a/b/c）。用户逐版打回，最后 v8.1 定稿、v9 发布成功。

真正有价值的不是「最后长什么样」，而是三次明确的否决理由 + 三次明确的认可理由。这些是真人判据，比任何教科书式的 AI 味清单都准。

正文三个关键版本：

- v1 · 初稿 400 字：纯事实叙述，无修辞。用户接受度最高。
- v3 · 故事感重写 525 字：加了身体反应、身份铺垫、伪坦诚、格言金句。用户判「AI 味儿很浓，也不好看」。
- v8 / v9 · 定稿 570 字：保留事实密度，删掉全部修辞与金句。发布成功。

## 二、被用户点名否掉的六类句式

这六类全部出自 v3，是真人眼里的 AI 味，不是学术定义里的 AI 味。

1. 身体反应修辞
   「我头皮麻了一下。」
   判词：加戏。事实是「摸到秃了一块」，情绪不用修辞，写动作就够。

2. 修辞性身份铺垫
   「我家猫身上哪块毛什么手感，我闭着眼都熟。」
   判词：自我表演。真人说「养了五年」就行，不需要「闭着眼都熟」这种对仗。

3. 伪坦诚 / staged candor
   「说实话，看到这句我反而信了。」
   判词：AI 味最重的一类。「说实话」本身不脏，脏的是「说实话」+「我反而信了」这种自我点评结构——它在替读者下结论。

4. 格言金句收尾
   「敢把「我不知道」写出来的，比什么都说满的可信。」
   判词：与上下文不搭 + 金句味。删掉之后信息一点没少。

5. 不是 X 而是 Y
   「它没甩给我一句模棱两可的话，而是把猫拆成四栏挨个说。」
   判词：这个句式在中文语境里已经是 AI 指纹级。

6. 无意义互动钩子
   「A 秃过是猫藓 B 秃过虚惊一场 C 还没遇到，先马住」
   判词：无意义。代价是放弃低门槛评论钩子，用户认了。

另外还有一类不是句式，是标签：「可能有人纠字。」这种自我预警句，真人不会写。

## 三、通过版本的六条写法规则

1. 用具体数字和具体动作替代形容词。65 分、扣 20、四栏、照灯、拔毛镜检——都是可核对的。
2. 承认边界要靠引用产品的原话，不要自己再加一句评价。产品说「照片只是局部，其余部位没法判断」，直接引，别再写「看到这句我反而信了」。
3. 情绪只用动作表达。「赶紧把猫翻过来看」比「我头皮麻了一下」有力。
4. 收尾落回读者的具体处境，不升华。「猫不舒服不会叫，只能靠你多看一眼」比任何金句都稳。
5. 图上只放正文里已经存在的句子。正文改字时图不用返工，也不会出现图文两套说法。
6. 引号内的产品输出必须和真机截图逐字一致。v6 起漏了「等异常」三个字，v8.1 才修回来。

## 四、视觉层的经验

平涂纯色 + 圆角卡片 + 胶囊徽标 + 几何页脚 = 最大的 AI 味来源，比文案更难救。

v3a 被评「AI 味儿很浓，也不好看」之后，v4 三个方向统一做了三件事：

1. 加胶片颗粒（±6~7 灰度噪声），破坏平涂感。
2. 去掉圆角卡片，改成整幅 bleed。
3. 去掉胶囊徽标和几何页脚，改用无衬线大字 + 细线分隔。

另一条纪律：不可靠的标注宁可跳过。原计划在照片上画红圈标出秃块位置，因为像素定位不可靠，2026-10-26 拍板跳过——画错位置等于伪造证据。

## 五、拿这套人判标准去测 flavor 项目

测试方法：13 条对抗样本 + 三个真实正文版本，直接调 `score_text` / `phrase_rewrite` / `detect_em_dash`。

### 5.1 13 条对抗样本结果

11 条真人判 AI 味的样本，`score_text` 全部返回 100 分、raw 0、零命中：

- 身体反应修辞 → 100 / 0 / 无命中
- 修辞性身份铺垫 → 100 / 0 / 无命中
- 伪坦诚「说实话」→ 100 / 0 / 无命中
- 伪坦诚「老实说」→ 100 / 0 / 无命中
- 格言金句 → 100 / 0 / 无命中
- 不是 X 而是 Y → 100 / 0 / 无命中
- 不是 X，是 Y → 100 / 0 / 无命中
- 单破折号 → 100 / 0 / 无命中
- 双破折号（中间夹字）→ 100 / 0 / 无命中
- 模板数字列举 → 100 / 0 / 无命中
- 营销腔「真的太懂养猫人了！」→ 100 / 0 / 无命中

唯一命中的是黑话对照样本「我们打造了端到端闭环，赋能宠物健康生态」→ 0 分，命中三条 tier1 词。

反向误伤一条：合规的健康提示句「也可能是猫癣，建议去医院照个灯」被 `p06_undue_caution` 判为过度谨慎，扣 2 分到 85 分。这在健康内容里是必要表达，不该罚。

### 5.2 三个真实版本结果

- v1（400 字，人接受）→ 100 分，raw 0
- v3（525 字，人判 AI 味很浓）→ 100 分，raw 0
- v8（570 字，人通过并发布）→ 100 分，raw 0

三个版本分数完全一样。评分器无法区分人判通过和人判否决，因此它给出的 100 分不能作为「可以发布」的判据。

### 5.3 规则改写层

`phrase_rewrite` 对上述 13 条样本 + 三个真实版本全部 NO-OP，一字未改。当前改写层只做词表级替换，不处理句式。

## 六、根因三条

### 根因 1：p01 有两套正则，scoring 用的是错的那套

`patterns/p01_not_x_but_y.py` 里的中文正则是 `不是…，而是`，能正确命中。

但 `scoring.py:237` 自己又写了一套：`r"不[仅只]?[^。]*?而[且却][^。]*?"`，只抓「不仅…而且」，抓不到「不是…而是」。

实测：文本「不是 A，而是 B」→ p01 模块命中 1 次，scoring 内置正则命中 0 次。所以 p01 在评分链路里基本失效，只在 `rewrite_text` 链路里生效。

同类风险：27 个 pattern 模块与 scoring 内置正则表是两套并行实现，存在系统性漂移。

### 根因 2：破折号正则写漏了

`detectors.py` 的 `EM_DASH_OVERUSE = r"——\s*——"` 要求两个破折号之间只有空白。所以「医生说——拍片——先看骨头」这种中间夹文字的写法完全不命中。

而我们的正文硬标准是 em dash 0 命中（连单个都不允许）。检测器比标准宽了一整档。

### 根因 3：pattern 体系是技术文档语域，不是社媒叙事语域

27 个 pattern 覆盖的是：综上所述、研究表明、值得注意的是、进行优化、该技术的应用、不仅而且、高效稳定可扩展……全是技术文档和 AI 摘要的指纹。

社媒叙事语域的 AI 指纹一个都没覆盖：身体反应、身份铺垫、伪坦诚、格言收尾、模板列举、营销感叹。

黄金集只有 11 条，全部是技术文档场景，没有一条社媒样本，也没有一条「人写的自然句不能扣分」的负样本。

## 七、优化方案

### P0 · 修错 + 补语域（预估 1~2 天）

1. `scoring.py:237` p01 正则改为复用 `patterns/p01_not_x_but_y.match`，删掉内置那套。顺带排查其余 26 个 pattern 是否有同样的双实现漂移，统一由模块提供正则（可加 `REGEXES` 导出）。
2. `detectors.py` 破折号改两级：单个 `——` 记 warn 不扣分，两个及以上扣分。对齐「正文 em dash 0 命中」的真实标准。
3. `p06_undue_caution` 加场景豁免：health/科普场景下「可能 / 也许 / 建议就医」不罚。
4. 新增 6 个 pattern（本次实战直接产出）：
   - `p28_body_reaction_cliche`：头皮发麻 / 后背发凉 / 心里咯噔 / 一口气提到嗓子眼
   - `p29_rhetorical_identity_setup`：干了 N 年 + 闭着眼都熟 / 作为一个 X / 见得太多了
   - `p30_staged_candor`：说实话 / 老实说 / 说句实话 / 坦白讲 + 后半句自我点评（需组合判定，单出现不罚）
   - `p31_aphorism_closer`：无主语的箴言判断句，`…比…更…` / `…才是…` / 敢把…的，比…
   - `p32_template_enumeration`：拆成 N 栏 / N 个维度 / N 点 / 三件套
   - `p33_marketing_exclamation`：真的太…了！/ 绝了 / 爱了 / 谁懂啊
5. 黄金集从 11 条扩到 40+ 条，新增两组：
   - 正样本 15~20 条：本次实战的六类被否句式
   - 负样本 10 条：人写的自然句，要求 raw 必须为 0（防止补 pattern 之后误伤真人口语）

验收标准（可脚本化）：13 条对抗样本至少 12 条命中；v3 分数 < v8 分数；负样本 10 条全部 raw 0。

### P1 · 补句式改写 + 评分校准（预估 2~3 天）

6. `phrase_rewrite` 加句式级改写器：不是 X 而是 Y → 保留后半句；格言句 → 整句删；身体反应句 → 删修辞保留事实动作。输出要带 diff 报告，人能看出改了哪。
7. 评分器加「句式层」独立子分，与词表层分开报。本次三个真实版本入库做 calibration set，硬要求 v3 < v8。这是把「人判」变成可回归的门槛。
8. `llm_detector` 目前 `enabled=False`、`provider="mock"`，实际不参与链路。要么接成第二判据（CLI 加 `--llm`），要么明确写进文档说它不是判据，别让人误以为有 LLM 兜底。

### P2 · 场景 profile（预估 2~3 天）

9. 引入 `scene` 参数：tech-doc / social-note / health-content。三套权重与词表分离，解决「可能」这类跨场景冲突。
10. 出评分回归报告：同一篇稿子改一版出一次分差说明，直接对得上小红书那种「改了 9 版」的工作流。

## 八、这次最值钱的结论

规则层的上限不是「词表不够大」，而是「语域不对」。这套 27 pattern 体系对着技术文档是准的，对着人写的社媒口播稿几乎全瞎——11 条真人判 AI 味的样本里漏了 11 条。

真正能抓住 AI 味的是句式结构（伪坦诚、格言收尾、不是 X 而是 Y、模板列举），单词级别的黑话表只能抓最表层那一层。

同时必须配负样本。pattern 加得越多，误伤真人口语的风险越大，而真人口语正是这个场景下唯一的正确答案。
